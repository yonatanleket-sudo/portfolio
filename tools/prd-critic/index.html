PRD-Critic

Most AI side projects generate more content. This one critiques it. PRD-Critic scores a product requirements document against a fixed, visible rubric — the same rubric a senior PM would use in review — and tells you exactly where it's not ready to build.

The rubric

Six dimensions, scored 1–5. This is the actual judgment layer — not the LLM call.

01

Problem Clarity

Is the problem specific and falsifiable, backed by evidence rather than assertion?

02

Success Metrics

Measurable targets with a baseline, a number, and a measurement window — not just direction.

03

Scope & Kill Criteria

What's in and out of scope, and a defined condition to stop, roll back, or reconsider.

04

Risks & Failure Modes

Specific risks with likelihood, impact, and mitigation — not a list of things that could go wrong.

05

Edge Cases

Non-happy-path scenarios enumerated for this specific feature, not generically gestured at.

06

AI-Specific Readiness

Model choice rationale, an accuracy threshold, a cost model, and a human-in-the-loop design.

How this works

Three states, in order of importance. Only the first one runs by default.

01 — ACTIVE ON THIS PAGE

Canned demo

The PRD and critique above are real content, precomputed and inlined directly into this page's HTML. No API key box exists here, and this page makes no network requests at all — open your browser's dev tools and check.

02

Run it live

Clone the repo and run the local critique script with your own Anthropic API key. The key is read from your environment and never touches a browser.

03

Eval harness

The credibility layer: a published protocol, a golden set, and how the critic's scores compare to independent human labels. See the methodology page.

# from the repo root
cd tools/prd-critic/local
npm install
export ANTHROPIC_API_KEY=sk-ant-...
npm run critique -- ../sample-prd.md
# or point it at your own PRD:
npm run critique -- /path/to/your-prd.md
ⓘ Why no key box. A static page has no trusted server to hold a key server-side. A pasted key is exposed to browser extensions, any XSS, and any future compromise of this page — and a visitor has no way to verify the page isn't sending it somewhere else. The local runner keeps your key on your machine, where it belongs.

Limitations

One sample PRD is not a benchmark. The rubric reflects one reviewer's (my) judgment about what makes a PRD buildable — reasonable people disagree on relative weighting. The structured-output schema is pinned by a fixture test (tools/prd-critic/local/schema.test.mjs), but that guarantees shape, not quality. Quality is what the eval protocol measures, and it's explicitly a pilot, not a claim that generalizes beyond the labeled set.
